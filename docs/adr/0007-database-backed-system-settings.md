# 0007. การย้ายการตั้งค่าระบบสู่ฐานข้อมูลและโมดูลบริหารจัดการหลังบ้าน

## สถานะ

ยอมรับแล้ว (Accepted)

## บริบท (Context)

เดิมทีข้อมูลการติดต่อ (เบอร์โทรศัพท์, อีเมล, ลิงก์ Facebook, ที่อยู่ทำการ) และข้อความอัตลักษณ์หน้าแรกถูกกำหนดค่าซ้ำซ้อนในไฟล์ `.env` และข้อมูลในระบบ ส่งผลให้ผู้ดูแลระบบไม่สามารถปรับปรุงข้อมูลติดต่อราชการได้ด้วยตนเองผ่านหน้าเว็บ อีกทั้งยังขัดกับหลักความปลอดภัยที่ระบุว่า `.env` ควรใช้สำหรับเก็บข้อมูลลับเฉพาะของระบบเท่านั้น (Environment Secrets)

## การตัดสินใจ (Decision)

1. **การจำกัดขอบเขตของไฟล์ `.env`**:
   - สงวนไฟล์ `.env` ไว้เฉพาะข้อมูลการเชื่อมต่อฐานข้อมูล (`DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`) และโหมดของระบบ (`APP_ENV`, `APP_DEBUG`) เท่านั้น
2. **การย้ายข้อมูลการติดต่อและอัตลักษณ์สู่ตาราง `settings`**:
   - จัดเก็บข้อมูลทั้งหมดในตาราง `settings` (รูปแบบ Key-Value ใน MySQL):
     - ข้อมูลอัตลักษณ์: `site_name`, `site_name_en`, `site_short`, `institute_name`, `hero_title`, `hero_intro`, `hero_caption`, `hero_image`
     - ข้อมูลการติดต่อ: `contact_phone`, `contact_email`, `contact_facebook_name`, `contact_facebook_url`, `contact_address`, `contact_hours`
     - สถิติหน้าแรก: `stat_courses`, `stat_labs`, `stat_employment`, `stat_mode`
3. **การพัฒนา `admin/settings.php` และการเรียกใช้ผ่าน `SettingService`**:
   - พัฒนาหน้าจอ `admin/settings.php` จัดแบ่งแท็บชัดเจน (ข้อมูลทั่วไป, ข้อมูลการติดต่อ, สื่อสังคมออนไลน์) เพื่อให้แอดมินแก้ไขข้อมูลได้อย่างสะดวก
   - ขับเคลื่อนผ่าน `SettingService` ซึ่งอ่านข้อมูลจากฐานข้อมูลเป็นหลัก และมีกลไก Fallback ไปยังฟังก์ชัน `env()` หากยังไม่มีการบันทึกในฐานข้อมูล พร้อมระบบแคชข้อมูลสั้น (60s) และล้างแคชทันทีที่มีการบันทึก

## ผลลัพธ์และข้อดี (Consequences)

- ผู้ดูแลระบบสามารถปรับปรุงข้อมูลติดต่อและอัตลักษณ์ของสาขาวิชาได้ทันทีผ่านหน้าบ้านของระบบจัดการ โดยไม่ต้องมีความรู้ด้านเทคนิคหรือสิทธิ์การเข้าถึงไฟล์ระบบ
- ความปลอดภัยของระบบเพิ่มขึ้นจากการจำกัดบทบาทของไฟล์ `.env` เฉพาะส่วนความลับทางเทคนิค
- ลดความซ้ำซ้อนของข้อมูล และป้องกันปัญหาข้อมูลในเว็บไซต์ไม่ตรงกับข้อมูลจริง
